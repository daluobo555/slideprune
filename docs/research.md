# SlidePrune 方向调研

调研日期：2026-10-03。结论是先做课件整理的本地原型，验证其使用价值。公开仓库证明这些问题已有人关注，不能据此推算市场规模或活跃用户。下文事实来自所链接的项目自述；没有把竞争者 README 的功能声明当作经过实测的性能结论，也没有复制其实现。

## 三个方向的比较

| 方向 | 已核验的直接竞争情况 | 本次选择判断 |
| --- | --- | --- |
| 截图敏感信息脱敏 | [Screenshot Redactor](https://github.com/cleanroom-ai/screenshot-redactor) 已提供浏览器本地 OCR、敏感信息检测、人工改框与图像导出；[RedactShot](https://github.com/darkzOGx/RedactShot) 提供本地截图、检测和复核流程。 | 需求容易解释，但本地处理和人工复核本身已无法构成明显差异；检测漏报还需要多语言样本验证。暂不投入。 |
| Docker Compose 环境变量诊断 | [compose-envkit](https://github.com/InfernalRabbit/compose-envkit) 使用 `compose-go`，提供变量来源追踪，以及服务 `env_file` 与插值变量之间的差异诊断。 | 与原先拟做的核心功能直接重叠；还需持续适配 Compose 行为。暂不投入。 |
| PDF 课件整理 | 已有重复页清理脚本，也有成熟度更高的浏览器讲义排版工具，具体如下。 | 尝试把逐步展开页的保守建议、逐页复核与讲义导出串成一个较短流程。这个组合是否值得切换，必须由用户验证。 |

## 课件方向也已有竞争者

| 项目 | 仓库中可核验的内容 | 对 SlidePrune 的含义 |
| --- | --- | --- |
| [prune-pdf](https://github.com/aconCS/prune-pdf) | 描述逐步展开课件重复的问题，并以 20 页变成 100 页举例；此次看到的仓库文件列表仅有 README。 | 是问题陈述，不是经过独立验证的用户规模、压缩比或完整可运行产品证据。 |
| [dedupdf](https://github.com/lmaraite/dedupdf) | Python/Conda 工作流；README 说明按标题和首行检查重复页。 | 说明已有轻量自动化方案。仅按标题判断的覆盖范围有限，但不能未经测试宣称 SlidePrune 更准确。 |
| [beamer-pdf-dedup](https://github.com/ReeseNoctis/beamer-pdf-dedup) | 命令行工具；说明相邻页比较、图像和独有文本检查、文本子集与近似度判断，提供 dry-run 和逐页说明。 | “保守删除”和“解释决定”已有先例。浏览器复核体验是本项目需要实际证明的便利性。 |
| [Nyquisis](https://github.com/Enoch2090/Nyquisis) | Python 命令行工具，清理重复 PDF 页，支持输入文件或目录。 | 本地处理和批处理已有方案；SlidePrune 首版没有批处理能力。 |
| [PDF Slides to Handouts Converter](https://github.com/flodlol/PDF-Slides-to-Handouts-Converter) | 浏览器本地处理、预览、选页、多种拼版、笔记线、页边距调整、隐藏重复元素。 | 是直接讲义竞品，排版选项比本原型丰富。“本地 PDF 拼版”不是空白市场。 |

因此，本项目不以“首创”“无竞品”“AI 自动不丢页”作为卖点。当前可验证的产品主张是：**拿到只有 PDF 的逐步展开课件时，先看懂整理建议，再少量操作导出可复习的讲义。**

## 为什么仍值得做一版

这是产品判断：问题能用一份自制课件直接展示；输入与输出明确；不依赖用户账号、外部模型、付费 API 或课程源文件；首版可以在本地验证完整流程。候选使用者包括学生、助教、教师和技术讲座读者，这只是待验证人群，尚无访谈或实际留存证据。

首版聚焦 PDF 相邻页；保留人工覆盖所有建议的入口；提供原尺寸、两页笔记和四页拼版。公式和图形通过原始 PDF 内容复制或嵌入，避免把导出质量限制为预览图片清晰度。算法只做启发式判断，必须允许使用者发现和纠正遗漏。

## 哪些结果会推翻这个选择

- 用户已有工具能同样快地完成任务，且不需要分组建议。
- 复核算法建议的时间接近或超过手动删页的时间。
- 常见真实课件存在难以察觉的错误排除，保守策略仍不足以减少风险。
- 用户只使用讲义排版，对清理逐步展开页没有需求；此时应重新定位或改进现有工具，而不是增加无关功能。

实际结果见[验证记录](verification.md)。目前没有真实用户试用或留存结果。
